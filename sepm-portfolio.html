Our SEPM Project

Multi-Layered Prompt Injection
Detection System

— SENTINEL X —

During our SEPM project, we designed and developed an Adversarial Prompt Detection System aimed at safeguarding system prompts from prompt injection attacks in AI-based applications. The project followed a structured engineering approach covering requirements analysis, system design, implementation, testing, and risk management.

The system architecture is a modular layered design implemented as a backend service exposed through a REST API. The detection pipeline processes every prompt through three sequential layers — rule-based, lexical anomaly, and semantic intent — before a decision fusion mechanism produces the final Safe / Unsafe classification. The system aligns with security principles: Confidentiality, Integrity, and Availability.

Detection Architecture

Three-Layer Defence Pipeline

Every prompt flows through three sequential detection layers. The moment any layer identifies a threat, an Early Exit Gateway fires — instantly blocking the prompt without wasting computation on deeper layers.

⚡
What is the Early Exit Gateway?
Traditional detection systems run every layer regardless of what earlier layers found — wasting CPU/GPU time on already-confirmed threats. Our Early Exit Gateway acts like a circuit breaker: after each layer evaluates the prompt, a gating function checks the result. If the layer returns ATTACK DETECTED, the entire pipeline halts immediately and fires a BLOCK response — skipping all subsequent layers. Only prompts that pass all three layers reach the Decision Fusion Module and receive an ALLOW verdict. This reduces average latency by up to 70% for obvious attacks and protects the most expensive semantic layer from unnecessary workload.

01
Rule-Based Detection
Explicit Pattern Matching
Scans every incoming prompt against a curated library of known jailbreak signatures, malicious command patterns, and system-override phrases using regular expressions. Zero ML overhead — pure pattern matching means sub-millisecond evaluation. First gate: if any regex fires, pipeline stops immediately.
Regex EngineKeyword Blacklist<1ms
02
Lexical Anomaly Detection
Character TF-IDF + LightGBM
Catches obfuscated attacks that avoid plain keywords (e.g. "H@ck", "h.a.c.k"). Converts prompts to character-level TF-IDF vectors — capturing structural oddities in character frequency. A LightGBM classifier trained on labelled injection datasets scores every prompt. Retrainable each sprint iteration with fresh false-positive/negative logs.
TF-IDF VectorsLightGBMObfuscation-Aware
03
Semantic Intent Detection
Sentence-BERT + Logistic Regression
The deepest, most powerful layer. Sentence-BERT converts the entire prompt into a dense semantic embedding — capturing meaning, context, and implied intent beyond surface words. A trained classifier evaluates the embedding to detect subtle, paraphrased, or indirect adversarial intent that no keyword or statistical approach could catch.
Sentence-BERTDense EmbeddingsIntent Analysis
DF
Decision Fusion Module
Rule Override + Score Fusion
Only reached if all three layers return PASS. Aggregates confidence scores from Layer 2 and Layer 3, applies rule-override logic (any hard-rule hit from Layer 1 always wins), and produces the final classification. Outputs a structured JSON verdict: {"decision":"safe","confidence":0.97}

Maintenance Model

Iterative Enhancement

Chosen because adversarial attacks constantly evolve — requiring continuous refinement, not a one-shot build.

📋
🧪
⚙️
🔍
SENTINEL
X
01
Baseline Implementation
Define core detection requirements, set up three-layer architecture, implement rule-based layer as a stable, zero-latency baseline.
02
Incremental Layer Improvement
Each detection layer improved independently. New jailbreak patterns added to Layer 1, LightGBM retrained on updated data, Sentence-BERT fine-tuned with novel attacks.
03
Log-Driven Feedback Loop
Every processed prompt generates a structured log. False positives and negatives are analysed to identify pipeline gaps and drive the next iteration's targeted improvements.
04
Stable Incremental Delivery
Major redesigns avoided. Small, targeted updates keep the system production-stable while continuously improving detection accuracy and performance metrics.
